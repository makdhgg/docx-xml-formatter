# 📄 DOCX XML Formatter & QA Sandbox

Продвинутый десктопный редактор форматирования `.docx` документов, написанный на Python. 
В отличие от стандартных библиотек, этот инструмент **напрямую парсит и модифицирует сырой OOXML** (Open XML) с помощью `lxml`, что дает полный контроль над структурой документа.

Особенность проекта — встроенный **режим Fault Injection (QA Sandbox)**, позволяющий тестировщикам тренировать навык поиска дефектов на специально внедренных, изолированных багах.

## 🚀 Возможности

- **Глубокий парсинг OOXML:** Извлечение и изменение стилей напрямую из `word/document.xml`.
- **Точечное и глобальное форматирование:** Изменение стилей как для отдельных прогонов (runs), так и для всего документа разом.
- **Работа с абзацами:** Настройка выравнивания, межстрочных интервалов и отступов (в сантиметрах, с автоматическим переводом в твипы).
- **Non-blocking UI:** Фоновая загрузка и сохранение документов через `threading` без фризов интерфейса.
- **Undo/Redo логика:** Глубокое копирование (`deepcopy`) XML-узлов (`rPr`/`pPr`) для безопасной отмены изменений.

## 🐞 QA Sandbox (Fault Injection Mode)

Проект содержит мастер-переключатель `BUGGY_MODE = True`, который внедряет в приложение **8 различных намеренных дефектов** (от логики UI до инверсии функций отмены). 

Каждый баг управляется своим флагом (`BUG_*`), что позволяет:
1. Изолированно тестировать конкретные сценарии.
2. Тренировать QA-инженеров на поиск как визуальных, так и логических/архитектурных дефектов.
3. Изучать паттерны внедрения и маскировки багов в коде (двойные ветки исполнения).

*Список багов и их описание можно найти в комментариях внутри `app.py`.*

## 🏗 Архитектура

Проект построен по принципу разделения ответственности:
1. **`gui_helper.py` (Model):** Отвечает за распаковку ZIP, парсинг XML и построение "карты" документа (список абзацев и прогонов со ссылками на оригинальные lxml-элементы).
2. **`formatter.py` (Engine):** Инкапсулирует всю работу с XML-деревом. Содержит методы двух типов: `change_*` (глобальные) и `apply_*` (точечные).
3. **`app.py` (View/Controller):** UI на базе `CustomTkinter`. Обрабатывает пользовательский ввод и делегирует работу движку.
